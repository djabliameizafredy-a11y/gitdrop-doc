Publier un projet ne devrait pas être un parcours du combattant

Pour un débutant, passer d’un dossier à un dépôt GitHub, c’est git init, add, commit, un remote, une branche, une authentification… et un risque : pousser un fichier .env avec une clé API, qui devient alors publique.

Gitdrop remplace tout cela par une seule commande guidée, et vérifie ce qui part avant que ce soit trop tard.

Déposez
un dossier, des fichiers ou un .zip — en CLI ou par glisser-déposer dans l’interface locale.
Gitdrop analyse
stack, fichiers sensibles, historique Git, .gitignore et README à générer.
Poussez
commit local, création du dépôt, push sur main, lien affiché — et site en ligne si vous le souhaitez.

Ce que Gitdrop apporte

Push en quelques secondes

Un dossier ou un .zip devient un dépôt GitHub : commit, création, push sur main. Les droits d’exécution des scripts sont conservés.

Secrets protégés

Une quinzaine de formats de clés reconnus (AWS, GitHub, OpenAI, Stripe…), .env exclus par défaut, et un .env.example sans valeurs créé pour vous.

Historique Git scanné

Un secret commité puis supprimé reste dans l’historique. Gitdrop le trouve, indique où révoquer la clé, et propose de ne publier qu’un commit propre.

Site en ligne

Site statique, Vite ou Create React App : GitHub Pages est activé et le workflow de déploiement ajouté, avec le bon chemin de base.

Après le premier push

Messages de commit générés depuis le diff, branche + pull request, push automatique à chaque modification (watch) et annulation sûre (undo).

Sans Node, si vous préférez

En plus de npm, un binaire autonome (Linux, macOS, Windows) avec l’interface intégrée. Il suffit d’avoir Git installé.

Et par rapport aux alternatives ?

Gitdrop ne réinvente pas Git : il s’appuie sur le vrai binaire git. Pour qui maîtrise déjà Git, gh repo create --source=. --push couvre le cas de base. La valeur de Gitdrop est autour.

Vos fichiers restent chez vous

Aucun serveur Gitdrop : l’outil tourne sur votre machine et ne parle qu’à GitHub. Votre jeton est stocké localement avec des droits restreints (0600) et n’apparaît jamais dans le projet, l’URL du remote ni la liste des processus.

Utiliser Gitdrop

De l’installation au site en ligne, en quelques commandes.

Installation

Prérequis dans tous les cas : Git installé et dans le PATH.

Le dépôt GitHub est public et peut être cloné par tous. Prérequis : Git, Node.js 20 ou plus récent et npm.

Clonez le dépôt, construisez l’application, puis liez la commande gitdrop à votre installation locale de Node.js.

$ git clone https://github.com/djabliameizafredy-a11y/gitdrop.git $ cd gitdrop $ npm ci $ npm run build $ npm link $ gitdrop --version
Le paquet gitdrop n’est pas encore publié sur npm. L’installation globale par npm install -g gitdrop n’est donc pas disponible. Utilisez l’installation depuis les sources ci-dessus.
Aucun binaire précompilé n’est encore publié. Les futurs installateurs et binaires seront disponibles dans les releases de Gitdrop. En attendant, utilisez l’installation depuis les sources.

Connexion GitHub

À faire une seule fois. Le Device Flow évite de copier un jeton à la main :

$ gitdrop login ✔ Code généré 1. Ouvre → https://github.com/login/device 2. Entre → ┌─────────────┐ │ ABCD-1234 │ └─────────────┘ ✔ Connecté : @vous

Autres options :

  • gitdrop login --token ghp_… — jeton personnel (scopes repo + workflow)
  • gitdrop login --gh — réutilise votre session GitHub CLI
  • Scripts / CI : variable GITDROP_TOKEN (ou GH_TOKEN / GITHUB_TOKEN)

Premier push

Donnez un dossier ou un .zip (le dossier courant par défaut). Gitdrop pose quelques questions :

$ gitdrop push ./mon-portfolio ✔ Projet analysé : ▲ Next.js — 42 fichiers (1.2 Mo) ⚠ Dossiers techniques ignorés automatiquement : node_modules ? 1 fichier(s) sensible(s) détecté(s). Cochés = exclus du push : .env ? Nom du dépôt GitHub : mon-portfolio ? Visibilité : Privé ? Ajouter un README ? Oui ? Message du commit : Initial commit ? Confirmer le push ? Oui ✔ Préparation des fichiers ✔ Création du commit ✔ Création du dépôt GitHub ✔ Envoi vers GitHub (branche main) 🔗 https://github.com/vous/mon-portfolio (44 fichiers)

Sans aucune question : gitdrop push ./projet --yes --public --name mon-projet. Le dépôt est privé par défaut. Il n’est créé qu’après le commit local : une erreur locale ne laisse jamais de dépôt vide, et un push interrompu se relance tel quel.

Interface locale

Pour glisser-déposer plutôt que taper : gitdrop ui ouvre une page sur localhost en quatre étapes — connexion, projet, configuration, envoi.

$ gitdrop ui # glisser-déposer un dossier ou un .zip $ gitdrop ui ./mon-projet # analyse le dossier sur place, avec son historique Git

Les navigateurs n’envoient jamais le dossier .git : pour analyser l’historique d’un projet, passez son chemin à gitdrop ui.

Protéger ses secrets

  • Fichiers sensibles (.env, clés privées, identifiants…) : exclus par défaut, et ajoutés au .gitignore. Un .env.example sans valeurs est créé à côté.
  • Clés dans le code : formats AWS, GitHub, OpenAI, Anthropic, Stripe, Slack, Google, SendGrid, npm, Twilio, Discord, Telegram, clés privées, URL de base de données, plus une détection par entropie. Les valeurs d’exemple sont ignorées.
  • Historique Git : si le dossier a déjà un .git, tout l’historique est analysé, même les fichiers supprimés depuis. Gitdrop affiche le lien pour révoquer chaque clé.
$ gitdrop push . --fresh-history # GitHub ne reçoit qu’un seul commit propre

Votre historique local reste intact. En mode non interactif, un historique contenant des secrets bloque le push, sauf avec --fresh-history ou --force. Une clé déjà commitée doit être considérée comme compromise : révoquez-la quand même.

Mettre un site en ligne

$ gitdrop push ./mon-site --public --deploy ✔ Publication sur GitHub Pages 🔗 https://github.com/vous/mon-site 🌐 https://vous.github.io/mon-site/ (en ligne dans ~1 minute)

Projets supportés : site statique (index.html), Vite et Create React App, avec le chemin de base /nom-du-dépôt/ géré. Pour un dépôt déjà poussé : gitdrop deploy.

GitHub Pages sur un dépôt privé exige un plan GitHub payant : le push réussit, et Gitdrop indique que le site n’a pas été publié. Next.js, Nuxt et SvelteKit ne sont pas supportés pour l’instant.

Après le premier push

$ gitdrop update # message généré : « feat: add login.js » $ gitdrop update "fix: bug" -b fix/bug --pr # branche + pull request $ gitdrop watch # pousse chaque modification (5 s après la dernière) $ gitdrop undo # annule le dernier commit poussé

Le message suit les Conventional Commits, choisi selon ce qui a changé (docs, test, chore(deps), ci, feat…). undo crée un commit d’annulation — jamais de force-push. update et watch refusent de pousser un fichier sensible sans --force.

Dépannage

Gitdrop utilise le binaire git. Installez-le depuis git-scm.com, puis rouvrez le terminal.

Le jeton n’a pas les bons droits. Relancez gitdrop login ; avec un jeton personnel, cochez repo et workflow.

Choisissez un autre nom. Si le dépôt existant est vide (push interrompu), Gitdrop le réutilise automatiquement.

GitHub refuse les pushs contenant certaines clés. Retirez-la du projet (ou de l’historique, avec --fresh-history), puis révoquez-la.

Lancez gitdrop ui --port 4000. Sans --port, Gitdrop essaie lui-même les ports suivants.
